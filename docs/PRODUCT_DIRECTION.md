# LUEMI 💜 — продуктовая директива: тест с друзьями → будущий публичный запуск

**Статус: обновлено владельцем 28 октября 2026. Текущая фаза — закрытый тест с друзьями.**

Это актуальное решение для разработки и развёртывания LUEMI. Владелец отменил **немедленный всеобщий запуск** и решил сначала протестировать приложение с несколькими приглашёнными друзьями. Открытие для всех — следующая стадия, только после обратной связи, функциональной готовности и необходимых процедур. Не выдавать закрытый тест за полный публичный запуск.

## Страна юридического запуска

**Республика Армения** — окончательный выбор владельца от 28 октября 2026 года, заменяющий ранее обсуждавшуюся Россию. Оператор — физическое лицо, ФИО и контакт указаны в неопубликованном [черновике политики](privacy-notice-draft-20261028.md).

Это решение **не открывает регистрацию автоматически** и не ограничивает аудиторию только Арменией. При международной аудитории необходимо отдельно проверить требования страны пользователей; действующие зарубежные дата-центры Render/Supabase требуют анализа трансграничной передачи по ст. 27 закона РА № HO-49-N. Не менять production-флаги `REM06_PRIVACY_APPROVED`, `REM06_OPEN_SIGNUPS_ENABLED` или `REM06_OPEN_SIGNUPS_APPROVED` до правовой и операционной готовности.

## Текущий этап: приглашённые друзья (28.10.2026)

**Действует закрытый тест, не публичный запуск.** Список приглашённых сверяется с подтверждённым Telegram ID, полученным с серверной проверкой подписи `initData`; посторонние не смогут создавать аккаунт по произвольной ссылке. Два ранее указанных владельцем аккаунта уже есть в закрытом списке; следующие друзья могут получить приглашение от владельца через `/myid` и отдельную операторскую процедуру. Все аккаунты проходят один и тот же реальный Telegram-вход без фальшивых анкет.

Разрешённая первая фаза: **реальные серверные сессии и частные черновики анкеты** с отдельным уведомлением [«Условия закрытого теста»](../apps/web/public/friends-test.html), осознанным чекбоксом и авторизацией. При повторном входе показывать сохранённый серверный профиль, а не заставлять проходить регистрацию снова. Пока не настроены и не проверены модерация и полноценное удаление данных, **не загружать персональные фото в Supabase, не публиковать анкеты, не запускать чаты/симпатии и не открывать регистрацию для всех**.

Активные настройки ограниченного теста: `REM06_FRIENDS_TEST_ENABLED=1`, `REM06_BETA_INVITES_ENABLED=1`, `REM06_PRIVATE_DRAFT_ENABLED=1`. `REM06_OPEN_SIGNUPS_ENABLED=0`, `REM06_MEDIA_ENABLED=0`, `REM06_PUBLICATION_ENABLED=0`, чаты и матчи выключены. Никакой автоматической юридической аттестации (`REM06_PRIVACY_APPROVED=0`). Реальное участие добровольно и 18+.

## Будущая аудитория

**Долгосрочная цель LUEMI — доступ для всех подходящих совершеннолетних пользователей Telegram.** После закрытого теста и готовности полноценной регистрации, фотографий, модерации и общения возможно переключение на открытый режим без приглашений. Не подменять этот будущий режим ранней бетой.

## Какой продукт должен работать

1. Telegram авторизация → настоящая серверная учётная запись → 8 шагов регистрации → сохранение черновика в PostgreSQL → приватная загрузка фото (3–6) → модерация фото → публикация → настоящие Discovery / профиль / взаимные симпатии / чаты.
2. После повторного входа зарегистрированный пользователь возвращается к своей опубликованной анкете, **не проходит регистрацию заново**.
3. В продуктивном интерфейсе не показывать синтетические анкеты, демонстрационную ленту или «тестовые» профили. Демо-поведение и fixtures разрешены лишь в явном локальном/dev/QA режиме.
4. Кнопка «Моё местоположение» после согласия использует Telegram LocationManager/GPS и определяет настоящий город через защищённый серверный геокодер. Только название города сохраняется в анкете; точные координаты — нет. Если геокодер недоступен, предоставить честный ручной выбор.
5. Регистрация **не требует персональных Telegram ID от владельца**; идентичность берётся только из проверенного Telegram `initData` и защищённых серверных сессий.

## Конфигурация будущего публичного выпуска (не включать сейчас)

- Выбранный admission mode: **OPEN**, не beta.
- Сервер: `REM06_OPEN_SIGNUPS_ENABLED=1` только **после** исполнения всех безопасных условий; `REM06_BETA_INVITES_ENABLED=0` всегда в публичном запуске. `REM06_OPEN_SIGNUPS_APPROVED=1` не ставить без реального подтверждения правил/политик.
- Рабочая среда: `REM05B_BOT_NAMESPACE=luemi-production`, чтобы не связывать публичные аккаунты с устаревшей beta-средой. План миграции существующих реальных записей требуется перед изменением namespace, если они появятся.
- Клиент: `VITE_LUEMI_REAL_ONLY=1`, `VITE_LUEMI_AUTH_V2=1`, настоящие draft/media/discovery/matches/chats интерфейсы **только после работоспособной серверной инфраструктуры**. Все `VITE_*` флаги компилируются в Vite и требуют нового билда.
- Две прежние записи в `luemi_private.beta_invites` не дают привилегий в открытом режиме. Они могут оставаться как история эксперимента; открытый вход не проверяет эту таблицу. Ничего не удалять только ради смены продуктовой стратегии.

## Обязательные требования безопасности перед публичным доступом

Нельзя изображать, что приложение уже открыто, если пользовательская регистрация реально не работает. Перед включением открытых регистраций нужны:

- Изолированные LOGIN роли и действительные SSL подключения PostgreSQL с принудительным RLS, без owner/service_role учётных данных в клиенте;
- Серверная верификация подписи и времени Telegram `initData`, cookie/CSRF сессии, лимиты запросов и защита от спама/злоупотреблений;
- Приватное Storage для фотографий, содержательная модерация фото, блокировки и жалобы, удаление/отзыв согласия;
- Актуальная опубликованная политика приватности и пользовательское согласие; проверить применимое право и требования платформы;
- Проверенные сохранение/восстановление анкет, публикация, discovery, взаимная симпатия, переписка, отсутствие доступа после блокировки;
- Подтверждённые тесты реальных аккаунтов и Android WebView. Тестирование на двух аккаунтах — только QA, **не ограничение аудитории**.

## Правило для следующих задач и агентов

**Текущий режим — закрытая реальная бета для друзей, согласованная с владельцем.** Разрешено добавлять новых приглашённых тестеров по подписанному Telegram ID без создания фальшивых пользователей. Не заменять реальную регистрацию демо-анкетами. Продолжать проектировать будущий **общедоступный** продукт, но не включать OPEN до отдельного решения владельца и фактической готовности. Не включать неработающие чаты, неподтверждённые публикации и автоматическое одобрение фотографий.

**Публичный запуск — продуктовая цель, но защитные ограничения нельзя обходить.** При неготовности инфраструктуры держать опасные server flags выключенными, исправлять конкретные блокеры и честно сообщать, что именно ещё не запущено.
