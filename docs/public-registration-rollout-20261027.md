# LUEMI 💜 — Публичный запуск, реальные аккаунты, публикация без очереди

**Режим:** все пользователи 18+ могут зарегистрироваться через проверенное Telegram WebApp initData. Никаких приглашений, фиктивных анкет и ручной предварительной модерации фото. Блокировки, жалобы, CSRF, RLS, приватное хранилище и удаление аккаунта остаются.

## Что реализовано в PR #122

1. `REM06_OPEN_SIGNUPS_ENABLED=1`, `REM06_BETA_INVITES_ENABLED=0`: вход любого настоящего Telegram-аккаунта с серверной криптографической проверкой initData.
2. После 8 шагов и загрузки 3–6 изображений сервер проверяет формат PNG, декодирует и очищает данные, проверяет размер/параметры, загружает только очищенные копии в **приватный** `luemi-profile-private`. Только для режима `REM06_AUTOPUBLISH_PHOTOS_ENABLED=1` с `REM06_AUTOPUBLISH_APPROVED=1` изображения сразу получают состояние `approved` без человеческой оценки содержания. **Такое состояние НЕ означает, что контент вручную проверен.** Пользователи обязаны соблюдать ограничения приложения; механизм жалоб, блокировок и последующего удаления остаётся.
3. Серверное опубликование требует активного авторизованного совершеннолетнего пользователя, действующего согласия, 3–6 успешно загруженных фото и корректного черновика. UI после публикации сразу открывает **настоящую ленту**. Повторный вход не запускает регистрацию заново.
4. `VITE_LUEMI_REAL_ONLY=1` убирает путь в синтетическую ленту из клиента, `apps/web/vite.config.ts` не компилирует отдельную страницу `chats-demo.html`. В тестовой конфигурации фикстуры остаются доступными для CI, но публичная сборка их не содержит.
5. В `/privacy` находится уведомление о персональных данных; через бота можно отправить сообщение `/support Текст вопроса`, которое пересылается в приватный чат владельца (если `LUEMI_SUPPORT_TELEGRAM_CHAT_ID` настроен). Пользователь может скрывать свою анкету и запросить удаление аккаунта (сначала немедленно отзывается доступ и создаётся очередь удаления).
6. Геолокация запрашивается только по нажатию кнопки; Telegram LocationManager или GPS телефона → приватный HTTPS reverse-запрос Geoapify; в анкету сохраняется только город. При недоступном геокодере пользователь выбирает город вручную.
7. Мэтчи и чаты работают только для настоящих опубликованных анкет. Сам пользователь не должен появляться в собственной ленте. Фотографии чата — в отдельном приватном bucket.

## Предварительные условия

- GitHub Environment `beta-bootstrap` должен быть **защищён required reviewer**. Пользователь/оператор добавляет в него четыре секретных значения (НЕ присылать их в чат и НЕ коммитить):
  - `BETA_SUPABASE_OWNER_URL`: точный **Session pooler** URL проекта `czzyoxrwtnvbicypwrdd` из Supabase → Connect, порт 5432.
  - `BETA_RENDER_API_KEY`: персональный API key владельца Render с правом редактировать сервис `srv-dbahj0e7bikc73elkcv0`.
  - `PUBLIC_SUPABASE_STORAGE_SECRET`: server-only secret Storage проекта LUEMI (формат `sb_secret_...` либо legacy service-role JWT), без браузерного экспорта.
  - `PUBLIC_GEOAPIFY_API_KEY`: API key геокодера для определения реальных городов. Серверная квота публичного запуска ограничена 100 запросами в день на весь сервис, 6 reverse на пользователя в день и 2 одновременными upstream запросами. Увеличивать лимит можно только после оценки нагрузки/тарифа.
- В Render должны существовать действующие `TELEGRAM_BOT_TOKEN`, `HEALTH_CHECK_KEY`, `APP_ORIGIN=https://luemi.onrender.com` и `LUEMI_SUPPORT_TELEGRAM_CHAT_ID` (приватный чат для обработки обращения). Последнее значение задаётся в Render, не в коде.
- До активации оператор должен **фактически проверить** текст `/privacy`, законность обработки данных, личность/реквизиты контролёра, каналы обращений, политику удаления, 18+ и правила обработки запрещённого/жалобного контента. Отсутствие ручной предварительной модерации не отменяет эти обязанности. Отдельный worker физического удаления может понадобиться для выполнения запроса на полную очистку.
- Таблицы, роли и RLS уже подготовлены. Нельзя использовать `postgres` или `service_role` для пользовательских HTTP-запросов.

## Как выполнить публичный выпуск одной операцией

1. На GitHub в репозитории `zhirayr2505/luemi` открой **Settings → Environments → beta-bootstrap** и внеси указанные четыре секрета; включи required reviewer. Не размещай их в issue/PR, коммитах и сообщениях.
2. Открой **Actions → LUEMI PUBLIC launch (operator-approved) → Run workflow**, выбери `main`.
3. Введи `RELEASE_PUBLIC_REAL_USERS` и поставь чекбокс о проверенном privacy notice и согласии на самопубликацию.
4. Один workflow выполняет:
   - `public-provision.mjs` → проверка NOLOGIN, при необходимости генерация девяти **разных** безопасных DB-паролей и установка их только в Supabase/Render через защищённый GitHub runner;
   - `public-release-activate.mjs` → проверка `session_user=current_user`, RLS, отсутствия общих прав, двух приватных buckets, готовности бота и storage, геокодера;
   - безопасная установка runtime и Vite флагов и **одна новая сборка** Render. На релизе активируются Telegram V2, открытые регистрации, приватное хранение, автопубликация, лента, мэтчи, чаты, геолокация и запросы на удаление;
   - проверка состояния деплоя и отказа неподписанному Telegram initData; при сбое после переключения запускается восстановление предыдущих Render environment.
5. Только **после** `LUEMI_PUBLIC_RELEASE_LIVE` тестируй приложение через бота. Отсутствие подтверждения статуса ≠ успех.

## Контроль после релиза

- Два настоящих пользователя регистрируются независимо, загружают 3–6 фото; обе анкеты должны получить `published`, никто не видит синтетические анкеты.
- Взаимные лайки открывают реальный чат, вход повторно восстанавливает профиль. Проверить загрузку фотографий чата, блокировку, отказ доступа чужим людям, паузу/восстановление сети.
- Третий произвольный Telegram пользователь тоже может зарегистрироваться, но до публикации остаётся невидимым.
- Физический Android WebView QA на Galaxy A55 и проверка обновления после закрытия Telegram.
- Команда `/support Вопрос` доставляет запрос в приватный чат оператора. Контент из закрытых Storage buckets не доступен анонимным ролям.
- Контролировать использование Geoapify и Supabase, права аккаунтов, жалобы, запросы удаления, abuse controls.

## Честный статус

Сама реализация **не равна запущенным аккаунтам**. До наличия четырёх защищённых секретов и фактического успешного manual GitHub Workflow нельзя утверждать, что публичная регистрация работает. Не переключать флаги напрямую, если не пройдены preflight и E2E.
